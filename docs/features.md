# ความสามารถของระบบ

กติกาธุรกิจและพฤติกรรมของแต่ละส่วน ยกมาจากเอกสารเดิมของโปรเจกต์ พฤติกรรมเหล่านี้ไม่เปลี่ยนจากการย้ายมา Laravel ดูวิธีติดตั้งและคำสั่งที่ [README.md](../README.md)

## กติกาธุรกิจ

1. โปรแกรมเป็น Private trip เฉพาะสมาชิกในกรุ๊ป ไม่ขายที่นั่งร่วมกับกรุ๊ปอื่น
2. เจ้าหน้าที่กำหนดวันเริ่ม/วันกลับ และราคาต่อคนแยกตามขนาดกรุ๊ปในแต่ละรอบ เช่น 6 คน และ 12 คน
3. ลูกค้าเลือกขนาดกรุ๊ปที่กำหนด ระบบคำนวณยอดรวม = ราคาต่อคน × ขนาดกรุ๊ป
4. ลูกค้าส่งคำขอ หรือเปิด LINE พร้อมข้อความโปรแกรม/รอบ/ขนาดกรุ๊ปให้ลูกค้าส่งเอง
5. คำขอไม่ตัดที่นั่ง ไม่รับเงิน และไม่ยืนยันอัตโนมัติ เจ้าหน้าที่ตรวจสอบและติดต่อกลับ
6. เก็บชื่อโปรแกรม วันเดินทาง และราคา ณ เวลาขอจองแยกไว้ การแก้โปรแกรมไม่เปลี่ยนประวัติคำขอเดิม

## หลังบ้าน

- ภาพรวม: จำนวนโปรแกรมและคิวคำขอ
- โปรแกรม: ข้อมูลพื้นฐาน รูปปก/แกลเลอรีและลำดับภาพ โปรแกรมรายวัน/ลำดับวัน โรงแรม รถ ไกด์ ช่างภาพ มื้ออาหารรายวัน เงื่อนไข รอบเดินทางและราคา
- สถานะโปรแกรม: ฉบับร่าง, เผยแพร่, เก็บถาวร พร้อมหน้าตัวอย่างที่ต้องล็อกอิน
- คำขอจอง: ใหม่, ติดต่อแล้ว, ยืนยันแล้ว, ยกเลิก และบันทึกภายใน
- ตั้งค่า: ตัวย่อรหัส, LINE Official ID, โทรศัพท์, อีเมล, ชื่อบริษัท และเปิด/ปิดแถบข้อมูลสาธิต

ตัวย่อรหัสแก้ไขได้ที่ `/admin/settings` (หรือ `/admin/setting`) ใช้ตัวอักษรอังกฤษและตัวเลข 1–10 ตัว ขึ้นต้นด้วยตัวอักษรอังกฤษ และบันทึกเป็นตัวพิมพ์ใหญ่ เมื่อบันทึกจะอัปเดต `tours.code` ของโปรแกรมทั้งหมด โดยคงส่วนหลังเครื่องหมายขีดไว้ เช่น `ZD-001` → `RV-001` และเก็บ `slug` เดิมไว้ รหัสเก่าแต่ละครั้งเก็บใน `tour_code_aliases` เพื่อลิงก์เดิมส่งต่อแบบ 301 ไปยังรหัสล่าสุด หากรหัสชนกันจะยกเลิกการบันทึกทั้งชุด เลขอ้างอิงการจองจะใช้ตัวย่อใหม่เฉพาะการจองใหม่ เช่น `RV-YYMMDD-XXXXXXXX` โดยประวัติการจองเดิมคงเดิม หากยังไม่ตั้งค่าจะใช้ `ZD`

โปรแกรมเผยแพร่ต้องมีรูปปก คำโปรย เงื่อนไข แผนรายวันครบ และรอบอนาคตที่เปิดรับคำขอพร้อมราคา ส่วนมื้ออาหารเริ่มต้นเป็นไม่รวมทั้งหมด

กรณีแก้ราคา/รอบขณะที่ลูกค้าเปิดหน้าเดิมอยู่ ลูกค้าจะต้องเลือกข้อมูลใหม่ก่อนส่งคำขอ ไม่รับราคาจาก client โดยตรง

## URL ของ Zone / Country / Route

Zone ใช้ `/tours/{slug}` เช่น `/tours/europe`, Country ใช้ `/tours/{slug}` เช่น `/tours/china` และ Route ใช้ `/tour/{country-slug}/{route-slug}` เช่น `/tour/china/chongqing` โดยตรวจว่า Route อยู่ภายใต้ Country ใน URL จริง หากประเทศไม่ตรงจะตอบ 404 ลิงก์ `/destinations/{kind}/{slug}` เดิมส่งต่อ 301 ไปยัง URL ใหม่และเก็บ query string ไว้

ลิงก์หน้าแรก breadcrumb จุดหมายในหน้าทัวร์ ปุ่มดูหน้าเว็บในหลังบ้าน ตัวอย่าง SEO, canonical, Open Graph และ sitemap ใช้รูปแบบใหม่นี้ Zone และ Country ต้องไม่ใช้ slug ซ้ำกันหรือชนกับรหัส/slug/ลิงก์เดิมของโปรแกรมทัวร์ รายละเอียดโปรแกรมยังใช้ `/tours/{code}` ตามเดิม ไม่ต้องย้ายข้อมูล

## ค้นหาทัวร์และแพ็คเกจ

ฟอร์มในหน้าแรก `/tours` และ `/packages` ใช้ autocomplete ร่วมกัน คลิกช่องค้นหาเพื่อเปิดจุดหมาย/เส้นทาง ทัวร์ และแพ็คเกจส่วนตัวยอดนิยม มีปุ่มเลือกประเภท พิมพ์เพื่อกรองด้วยชื่อ รหัสโปรแกรม slug ประเทศ หรือเส้นทาง รองรับหลายคำ เช่น `china kunming` และเลือกด้วยปุ่มลูกศร/Enter หรือปิดด้วย Escape คลิกคำแนะนำเพื่อเปิดหน้าโปรแกรมหรือ URL จุดหมายแบบใหม่ กดค้นหาทั้งหมดเพื่อใช้ประเภทโปรแกรมและตัวกรองเดือน/ช่วงวันที่จากฟอร์ม

หน้า Zone, Country และ Route เช่น `/tour/china/kunming` มีฟอร์มค้นหาและ autocomplete เดียวกัน โดยค้นหาภายในจุดหมายนั้น ค่าเริ่มต้นแสดงทุกประเภท เลือกทัวร์/แพ็คเกจส่วนตัวและเดือน/ช่วงวันที่ได้ การส่งฟอร์มและล้างตัวกรองยังอยู่บน URL จุดหมายเดิม canonical ไม่รวม query string หากต้องการออกจากจุดหมายให้ใช้ลิงก์ “ค้นหาทุกจุดหมาย”

คำแนะนำใช้เฉพาะโปรแกรมเผยแพร่และจุดหมายที่มีโปรแกรมเผยแพร่ ในหน้าจุดหมาย หากช่องค้นหาว่างจะแนะนำโปรแกรมของจุดหมายปัจจุบัน เมื่อพิมพ์คำใหม่จะค้นหา autocomplete จากทุกจุดหมาย เช่น อยู่หน้าคุนหมิงแล้วพิมพ์เชียงใหม่ เลือกคำแนะนำเพื่อเปิดหน้าใหม่ได้ทันที การเปลี่ยนคำค้นจะรีเซ็ตหมวดใน popup เป็น “ทั้งหมด” และแทนที่รายการเดิม เมื่อเคลียร์ข้อความจะกลับไปแสดงรายการยอดนิยมของจุดหมายปัจจุบัน

จัดอันดับคำแนะนำด้วยจำนวนการจองที่ยืนยันแล้ว ตามด้วยโปรแกรมแนะนำและลำดับแสดงผล โหลดดัชนีขนาดย่อพร้อมหน้าเว็บครั้งเดียว แล้วกรองในเบราว์เซอร์โดยไม่ส่ง request ระหว่างพิมพ์

## นำเข้า Zone / Country / Route จาก JSON

หน้า `/admin/destinations/zone/new`, `/admin/destinations/country/new` และ `/admin/destinations/route/new` เริ่มจากพิมพ์หัวข้อ เช่น ยุโรป / ญี่ปุ่น / โตเกียว–ฟูจิ และเลือกรายการแม่สำหรับ Country หรือ Route จากนั้นกด “สร้างและคัดลอก Prompt” ไปให้ AI เขียนคำอธิบาย เสนอ URL Slug และ SEO แล้วนำ JSON กลับมาวางหรือเลือกไฟล์ `.json` ไม่เกิน 2 MB ไม่จำเป็นต้องมี PDF

นำเข้าทีละรายการและตรวจทานในฟอร์มเดิม: Zone ไม่มีรายการแม่, Country จับคู่ Zone, Route จับคู่ Country ด้วยชื่อ/slug ที่มีอยู่จริง Prompt ระบุหัวข้อ รายการแม่ที่ผู้ใช้เลือก และลำดับแสดงผลจากฟอร์ม เมื่อแก้หัวข้อหรือรายการแม่ต้องกดสร้าง Prompt ใหม่ ระบบแจ้งข้อมูลขาด URL ซ้ำ และชนิด JSON ไม่ตรง AI เสนอเนื้อหาจากความรู้ทั่วไปที่มั่นใจ ไม่แต่งราคา โปรโมชั่น หรือข้อมูลบริการบริษัท ช่องที่ไม่แน่ใจใช้ null ให้ผู้ใช้ตรวจสอบ

แนบ PDF ต้นฉบับได้ทั้งสามประเภท (สูงสุด 10 MB) และแนบรูปธงใน Country ก่อนกดบันทึกครั้งเดียว PDF เก็บใน `storage/destination-pdfs` และเปิดผ่านผู้ดูแลที่เข้าสู่ระบบเท่านั้น การบันทึกล้มเหลวจะล้างไฟล์ใหม่ การแทนที่ PDF หรือลบจุดหมายสำเร็จจะล้างไฟล์เก่า

## นำเข้าทัวร์จาก JSON / PDF

เข้า `/admin/tours/add` หรือ `/admin/tours/new` เลือกประเภทก่อนคัดลอก Prompt: ทัวร์ปกติใช้วันไป–กลับ ที่นั่ง และราคาต่อรอบ ส่วนแพ็คเกจส่วนตัวใช้ช่วงเปิดขาย วันงดเดินทาง จองล่วงหน้า และเรตราคาตามระดับบริการ/จำนวนคน Prompt มีเฉพาะโครงสร้างของประเภทที่เลือก พร้อมรายการจุดหมายและระดับบริการปัจจุบัน นำ Prompt กับ PDF ไปให้ AI แล้ววาง JSON หรือเลือกไฟล์ `.json` ในหน้าเดิม ระบบปฏิเสธ JSON ที่ประเภทไม่ตรงหรือใช้โครงสร้างราคาผิดประเภทก่อนเปลี่ยนข้อมูลในฟอร์ม

ระบบเติมฟอร์มและรายการรายวัน/รอบ/ราคาให้ตรวจทาน แจ้งข้อมูลขาดหรือจับคู่ไม่ได้ ไม่สร้างจุดหมายจากชื่อที่ AI ส่งมาเอง ค่าอาหารและบริการที่ไม่ระบุเก็บเป็น NULL ข้อมูลที่จำเป็นต้องกรอกให้ครบก่อนบันทึก การนำเข้าเริ่มเป็นฉบับร่างและปิดรับคำขอทุกรอบ ราคาเด็กหรือราคาที่ไม่มีช่องรองรับให้เก็บรายละเอียดในเงื่อนไขตาม Prompt

ข้อความทุกช่องจะแสดงให้ลูกค้าเห็น Prompt จึงให้ AI ใส่ข้อขัดแย้งและข้อสังเกตถึงผู้ดูแลไว้ใน `review_notes` ซึ่งแสดงเฉพาะในรายงานหลังนำเข้าและไม่ถูกบันทึก ระบบยังเตือนเมื่อพบคำอย่าง "เอกสาร" "หน้าปก" หรือ "ไม่ระบุ" ในช่องที่ลูกค้าเห็น

แนบรูปภาพและ PDF ต้นฉบับแยกจาก JSON ในฟอร์มเดียว PDF สูงสุด 10 MB เก็บใน `storage/tours/{tour_id}/doc` ดาวน์โหลดผ่านผู้ดูแลที่เข้าสู่ระบบเท่านั้น รูปปก/รูปแกลเลอรี/รูปรายวันใช้ช่องอัปโหลดเดิมและเก็บใน `public/uploads/tours/{tour_id}/images` (ไฟล์เก่าที่อยู่ใน `public/uploads` และ `storage/tour-pdfs` ยังใช้งานได้ตามเดิม) เมื่ออัปโหลด PDF รูปปก หรือรูปรายวันทับของเดิมและบันทึกสำเร็จ ระบบจะลบไฟล์เดิมหากไม่มีข้อมูลส่วนอื่นอ้างถึง บันทึกทัวร์และรายการย่อยใน transaction เดียว หากบันทึกล้มเหลวไฟล์ใหม่จะถูกล้างและต้องเลือกแนบใหม่

## นำเข้าระดับบริการจาก JSON / PDF

หน้า `/admin/package-levels/new` คัดลอก Prompt ไปให้ AI พร้อม PDF แล้ววาง JSON หรือเลือกไฟล์ `.json` ไม่เกิน 2 MB ในรูปแบบ `{"schema_version":1,"kind":"package_levels","levels":[{"name":"..."}]}` Prompt แนบรายชื่อระดับปัจจุบันเพื่อให้ AI ใช้ตัวสะกดเดียวกัน

ระบบข้ามชื่อที่มีอยู่แล้วหรือซ้ำใน JSON โดยไม่แก้ไขระดับเดิม ลำดับเริ่มต่อจากค่าสูงสุดในระบบและแก้ไขได้ก่อนบันทึก การบันทึกทำทุกแถวใน transaction เดียว หากมีแถวไม่ผ่านจะไม่บันทึกเลยและคงรายการไว้ให้แก้ไข

## หน้ารวม 3 ประเภทและการ์ดเส้นทาง

เว็บขายโปรแกรม 3 แบบ แต่ละแบบมีหน้ารวมของตัวเอง:

| หน้า | URL | เงื่อนไข |
|---|---|---|
| ทัวร์รวมตั๋ว | `/tours-with-flight` | `program_type=fixed` และ `flight_included=1` |
| ทัวร์ไม่รวมตั๋ว | `/land-tours` | `program_type=fixed` และ `flight_included=0` |
| แพ็คเกจส่วนตัว | `/packages` | `program_type=private` |

หน้าแรกส่วน `#featured` แสดงหมวดด้านซ้ายและ slider การ์ดทัวร์ด้านขวา เรียงทัวร์ไม่รวมตั๋ว ทัวร์รวมตั๋ว แพ็คเกจส่วนตัว และซ่อนหมวดที่ไม่มีโปรแกรมเผยแพร่ แต่ละหมวดแสดงเฉพาะโปรแกรมที่ติ๊ก “แสดงในทัวร์แนะนำหน้าแรก” หากหมวดนั้นยังไม่มีโปรแกรมที่ติ๊กจะแสดงทุกโปรแกรมแทน หมวดละไม่เกิน 8 ใบ ส่วนตัวเลขบนหมวดนับโปรแกรมเผยแพร่ทั้งหมดของหมวด บนจอกว้างกว่า 960 px การ์ดเลื่อนเองทุก 4.5 วินาที และหยุดเมื่อวางเมาส์ โฟกัสอยู่ในส่วนนี้ เลื่อนจอออกนอกส่วนนี้ ปิด motion ของเว็บ หรือตั้งค่าลดการเคลื่อนไหวไว้ บนมือถือปัดเลื่อนเอง

`/tours` ยังเปิดอยู่เป็นหน้ารวมทัวร์ทั้งแบบรวมและไม่รวมตั๋ว และเป็นปลายทางของปุ่ม “ทัวร์ทั้งหมด” ในหน้าแรก โปรแกรมเก่าที่ไม่ได้ตั้งค่าเรื่องตั๋วจะเป็น “ไม่รวมตั๋ว” ต้องตรวจในหลังบ้านที่ **โปรแกรม → ข้อมูลพื้นฐาน → ตั๋วเครื่องบิน** ค่านี้เป็นคนละเรื่องกับช่องสายการบิน ระบบไม่เดาจากชื่อสายการบิน ค่าจะถูกเก็บลงการจอง ณ เวลาส่งคำขอและแสดงในเอกสาร ส่วนการจองก่อนมีคอลัมน์นี้เป็น `NULL` และไม่แสดงข้อความเรื่องตั๋ว

หน้ารวมแสดงการ์ดเส้นทางเหนือรายการโปรแกรม สร้างจากผล `listing()` จึงใช้ราคาและรอบเดียวกับการ์ดโปรแกรม รูปการ์ดใช้รูปปกของ Route ถ้าไม่มีใช้รูปของโปรแกรมแรก เรียงตามจำนวนโปรแกรมในเส้นทาง:

- มี 1–3 เส้นทาง: การ์ดหลัก 1 ใบ และคอลัมน์ข้าง 2 ใบ ช่องที่ยังว่างเติมด้วยเส้นทางจากประเภทอื่นที่มีรอบเปิดอยู่ พร้อมป้ายบอกประเภท
- มีตั้งแต่ 4 เส้นทาง: การ์ดใหญ่ 2 ใบ ที่เหลือเป็นการ์ดเล็ก และไม่แสดงเส้นทางจากประเภทอื่น
- เมื่อค้นหาหรือกรองวันที่: ซ่อนการ์ดเส้นทางและลิงก์ประเภทอื่น แล้วแสดงเฉพาะผลลัพธ์

การ์ดลิงก์ไปหน้าเส้นทางพร้อม `?program_type=flight|land|private` เพื่อกรองประเภทเดิม canonical ยังไม่รวม query string และ breadcrumb พากลับหน้าประเภทนั้น แพ็คเกจส่วนตัวแสดงตารางราคาตามจำนวนคนในหน้ารวม สลับระดับบริการได้ โดยใช้เรตของช่วงเดินทางแรกที่เปิดอยู่

## สายการบินและเที่ยวบิน

จัดการสายการบินที่ **หลังบ้าน → สายการบิน** (`/admin/airlines`, สิทธิ์เดียวกับโปรแกรมทัวร์): ชื่อ รหัส โลโก้ ลำดับ และการเปิดใช้งาน โลโก้แนะนำ 600 × 200 พิกเซล แนวนอน 3:1 พื้นโปร่งใส รองรับ PNG, WebP, JPG ไม่เกิน 1 MB ไฟล์อยู่ใน `public/uploads/airlines` ระบบไม่ตัดรูปให้ จึงควรตัดพื้นที่ว่างรอบโลโก้ก่อนอัปโหลด ถ้าไม่มีโลโก้จะแสดงรหัสแทน สายการบินที่มีโปรแกรมใช้อยู่ลบไม่ได้ ให้ปิดการใช้งานแทน

ในฟอร์มโปรแกรม ส่วน **เที่ยวบิน** สร้างเป็น “ชุดเที่ยวบิน” แล้วเลือกชุดให้แต่ละรอบในส่วนวันและราคา รอบที่บินเหมือนกันจึงใช้ชุดเดียวกันได้ ถ้ามีชุดเดียวระบบเลือกให้ทุกรอบเอง ทัวร์รวมตั๋วที่ยังมีรอบเปิดอยู่แต่ไม่ได้เลือกชุดจะบันทึกได้ และแจ้งเตือนหลังบันทึก

- แต่ละเที่ยวเป็นขาไป ตั๋วภายใน หรือขากลับ และกำหนดรวมหรือไม่รวมในราคาทัวร์ได้เป็นรายเที่ยว
- ระยะเวลาบินกรอกเองในรูปแบบ ชม:นาที เพราะเวลาออกและถึงเป็นเวลาท้องถิ่น คำนวณข้ามเขตเวลาไม่ได้
- แพ็คเกจส่วนตัวไม่มีตารางบิน เพราะลูกค้าเลือกวันเดินทางเอง และระบบไม่เก็บชุดเที่ยวบินของโปรแกรมประเภทนี้
- ค่าเดิมในช่อง `tours.airline` ยังเก็บไว้ และใช้แสดงบนการ์ดเฉพาะโปรแกรมที่ยังไม่มีเที่ยวบิน

การแสดงผล: การ์ดทัวร์รวมตั๋วมีแถวโลโก้พร้อมเลขเที่ยวบินและเวลาออกใต้ชื่อทัวร์ ถ้ารอบที่เปิดอยู่ใช้หลายชุดจะแสดง “เที่ยวบินตามรอบเดินทาง” การ์ดทัวร์ไม่รวมตั๋วเป็นข้อความโดยไม่มีโลโก้ เพื่อไม่ให้เข้าใจว่าราคารวมตั๋ว หน้าโปรแกรมเปลี่ยนเที่ยวบินตามรอบที่เลือกในกล่องจอง

ทัวร์ไม่รวมตั๋วและแพ็คเกจส่วนตัวมีปุ่ม “ให้ทีมงานช่วยจองตั๋ว” ซึ่งเลือกตัวเลือกในฟอร์มจอง ค่า `bookings.ticket_help` แสดงในหน้าการจองของทีมงานและลูกค้า ราคาตั๋วแยกจากยอดคำขอจอง ทีมงานแจ้งราคาจริงให้ลูกค้ายืนยันก่อนซื้อ เที่ยวบินของรอบที่จองถูกเก็บลง `bookings.flight_snapshot` การแก้โปรแกรมภายหลังจึงไม่เปลี่ยนประวัติเดิม

นำเข้า JSON รองรับ `flights` สำหรับทัวร์ปกติ โดยสร้างเป็นชุดเดียวชื่อ “ชุดหลัก” และจับคู่สายการบินจากชื่อที่มีในระบบ ไม่สร้างสายการบินใหม่เอง

## ประเภทโปรแกรมและแพ็คเกจส่วนตัว

- หลังบ้านเลือกประเภท “โปรแกรมเดิม” หรือ “แพ็คเกจส่วนตัว”; โปรแกรมที่มีการจองแล้วเปลี่ยนประเภทไม่ได้
- แพ็คเกจส่วนตัวกำหนดช่วงเดินทางที่ไม่ซ้อนกัน วันจองล่วงหน้า วันงดเดินทาง และหลายเรต Normal / Luxury / Premium ในแต่ละพีเรียดได้
- แต่ละเรตมีจำนวนคนขั้นต่ำ–สูงสุด ราคาต่อคน และรายละเอียดบริการ ช่วงจำนวนคนในระดับเดียวกันต้องไม่ซ้อนกัน
- ลูกค้าเลือกวันเริ่มเดินทาง ระบบคำนวณวันกลับตามจำนวนวันของโปรแกรม ทั้งทริปต้องอยู่ในช่วงและไม่คร่อมวันงดเดินทาง
- แต่ละ booking เป็นกรุ๊ปแยกกัน เจ้าหน้าที่ต้องตรวจความพร้อมของบริการก่อนยืนยัน ไม่มีการหักที่นั่งร่วมกันในพีเรียดส่วนตัว
- ราคา ระดับบริการ และเงื่อนไขมัดจำของแพ็คเกจถูกเก็บ ณ เวลาส่งคำขอ ใบแจ้งหนี้ใช้วันเดินทางที่ลูกค้าเลือก
- เวอร์ชันนี้ใช้เรตต่อคนเดียวกันสำหรับผู้เดินทางทุกคน หากต้องการราคาเด็กหรือจำนวนที่ไม่มีเรตให้สอบถามทีมงาน

ระดับบริการจัดการได้ที่ **หลังบ้าน → ระดับบริการ**: เพิ่มชื่อ แก้ชื่อ/ลำดับ ดูโปรแกรมที่ใช้งาน และลบระดับที่ไม่ได้ใช้ในพีเรียด ชื่อใหม่จะแสดงในโปรแกรม ส่วนรายการจองเดิมคงชื่อ ณ เวลาจองไว้

## Admin accounts and role permissions

Existing administrators become Super Admin only on the first migration; new database inserts without a role receive no access. Re-running the migration preserves role assignments and permissions.

- `/admin/admins`: search, create, edit, reset passwords, assign one role per account, and deactivate accounts without removing historical references.
- `/admin/roles`: create roles, select module permissions, and delete unused roles. Each permission grants both viewing and management of that module.
- Super Admin is immutable and has all permissions. Delegated managers can assign only roles and permissions they already hold; they cannot edit their own role permissions.
- Accounts cannot deactivate themselves or change their own role. At least one active Super Admin must remain.
- Permissions and account status are read on every protected request. Password resets invalidate existing sessions. After upgrading, administrators must sign in again.
- Restricted accounts see a workspace containing their permitted modules instead of the booking dashboard. All protected controller actions enforce authorization, including direct controller URLs and passport downloads.

## Tracking: GTM, Meta Pixel and LINE Ads Tag

Configure `/admin/settings` under **Tracking — GTM / Facebook / LINE**. The default is off. Enter IDs only; executable snippets are not accepted. LINE Ads Tag ID is a UUID from LINE Ads, separate from the LINE Official ID used for chat links.

Choose one installation owner:

- **GTM** loads the configured container after consent. Configure GA4, Meta and LINE tags and their event triggers in that container. Direct pixel IDs saved in the form are ignored in this mode.
- **Direct** loads Meta Pixel and/or LINE Ads Tag after consent. GTM is ignored in this mode.

The browser emits `page_view`, `view_item`, `search`, `begin_checkout`, `booking_submit`, `contact_click` and `generate_lead` in `window.dataLayer`. Product details live in `ecommerce.items`; a successful lead includes `event_id`, `currency`, `value` and `ecommerce`. Contact clicks include `contact_channel`. The site does not send free-text search terms, contact fields, messages, booking access tokens or full outbound contact URLs in these events. Treat a contact click as an attempt to open a channel; it does not establish that a message was sent.

In GTM, use Custom Event triggers with these exact names. Avoid counting `page_view` both through an automatic GA4 page view and a custom event tag. Map `generate_lead` to Meta Lead / LINE Conversion; never map `booking_submit` or `contact_click` to a completed booking or Purchase. Review container tags for automatic form collection and consent settings before publication; the site cannot validate tags configured inside an external container.

Direct Meta events map to PageView, ViewContent, InitiateCheckout, Contact and Lead. Direct LINE sends `pv`, custom `cv` event types for interactions, and `Conversion` only after a saved booking request. No Purchase event is emitted because a booking request is not a payment.

Consent defaults to denied. Vendor libraries are blocked until acceptance. A choice expires after 180 days and can be changed using the cookie settings button; withdrawal reloads the page to stop all libraries. The booking form's data-use checkbox is independent of tracking consent. Admin, preview, passport, customer booking and payment pages contain no tracking loader. Addresses containing arbitrary query input and referrers containing query strings or private routes also suppress SDK loading, so those visits can be absent from advertising reports. The route-card filter `program_type` is exempt because its values come from a fixed list.

After the booking transaction commits, the session carries one anonymous lead event to `/booking/success`. When tracking is configured, this page displays a generic success message and a button to continue to the private booking details; it contains no customer name, reference or access token. Refreshing or revisiting success redirects to the details without another lead. With tracking off, the original immediate redirect remains. Browser conversion tracking is best effort: blockers, refusal, navigation before consent, or an unavailable SDK can prevent delivery; account-side receipt still requires verification with actual IDs.

Provider references: [Google basic consent mode](https://developers.google.com/tag-platform/security/guides/consent?consentmode=basic), [LINE event tracking](https://www.lycbiz.com/jp/manual/line-ads/tracking_021/).

## หัวข้อราคาและเงื่อนไขในหน้าโปรแกรม

หน้าโปรแกรมแยก "รวมในราคา" กับ "ไม่รวมในราคา" เป็นรายการ แล้วแยกการชำระเงิน การยกเลิก และ "ควรรู้ก่อนเดินทาง" ออกจากเงื่อนไขอื่น แก้ได้ในหน้าแก้ไขโปรแกรมและนำเข้าจาก JSON ได้ ช่องแบบรายการใช้หนึ่งข้อต่อบรรทัด ช่องที่ว่างจะไม่แสดง ก่อนเผยแพร่ต้องมีอย่างน้อยหนึ่งช่องจากการชำระเงิน การยกเลิก หรือเงื่อนไขอื่น

ระดับบริการ Standard กับ Economy คือระดับเดียวกัน Prompt นำเข้าจึงให้ใช้ชื่อ Economy

## ดูราคาในกล่องจอง

ฟอร์มหน้าโปรแกรมให้ลูกค้าเห็นราคาก่อนกรอกข้อมูลติดต่อ ราคาบนหัวกล่องจองและแถบล่างบนมือถือเปลี่ยนตามที่เลือก แพ็คเกจส่วนตัวเลือกระดับบริการและจำนวนคนได้ก่อนเลือกวัน โดยแสดงเป็นราคาเริ่มต้นจากเรตที่ต่ำที่สุดของระดับและจำนวนนั้น เมื่อเลือกวันจึงเป็นราคาจริงของช่วงนั้น

หน้าโปรแกรมแบ่งฟอร์มเป็น 2 สเต็ปและอยู่ในจอแรกโดยไม่ต้องเลื่อนหน้า สเต็ป 1 เลือกรอบ จำนวนคน และห้องพัก สเต็ป 2 กรอกข้อมูลติดต่อและหมายเหตุ พร้อมการ์ด “สรุปทริปของคุณ” ที่กดคัดลอกไปวางในแชทได้โดยไม่ต้องกรอกฟอร์ม ข้อความที่คัดลอกมีรายการในการ์ดและลิงก์หน้าโปรแกรม ปุ่มแชทใช้ LINE Official ID จาก `/admin/settings` และลิงก์ Messenger จากหน้าตั้งค่าการติดต่อ บนจอกว้างไม่เกิน 900px ฟอร์มจะเปิดเป็นแผ่นเลื่อนขึ้นจากปุ่มด้านล่าง

แพ็คเกจส่วนตัวเลือกวันจากปฏิทินในกล่องจอง วันที่เปิดให้กดใช้กติกาเดียวกับการจองจริง ได้แก่ ช่วงที่เปิดขาย จองล่วงหน้า วันงดเดินทางตลอดทริป และต้องมีเรตของระดับและจำนวนคนที่เลือก ถ้าเดือนนั้นมีหลายราคาจะแสดงราคาต่อคนในแต่ละวัน ถ้าราคาเดียวจะแสดงใต้ปฏิทิน หน้าสร้างการจองในหลังบ้านยังใช้ช่องวันที่ปกติ

ระบบจัดห้องเริ่มต้นตามจำนวนคน คู่ใช้ห้องคู่ทั้งหมด คี่ใช้ห้องพัก 3 คนหนึ่งห้อง และคนเดียวใช้ห้องเดี่ยว ลูกค้าเปลี่ยนได้ และเมื่อแก้เองแล้วระบบจะไม่จัดทับ ช่องข้อมูลติดต่อเปิดเมื่อยอดครบแล้ว หน้าสร้างการจองในหลังบ้านยังใช้ขั้นตอนเดิม

## โรงแรมรายวัน

แต่ละวันเพิ่มโรงแรมได้หลายแห่งตามลำดับ โรงแรมที่ 1 คือโรงแรมหลัก และโรงแรมถัดไปคือตัวสำรองเมื่อโรงแรมก่อนหน้าไม่ได้ แต่ละโรงแรมมีกี่รูปก็ได้ ไม่เกิน 5 MB ต่อรูป เรียงลำดับโรงแรมและรูปได้ และคัดลอกจากวันก่อนหน้าได้สำหรับการพักหลายคืน

รูปอัปโหลดทีละไฟล์ผ่าน `/admin/tours/hotel-photo` ทันทีที่เลือก จึงไม่ชน `max_file_uploads` ของ PHP แต่รายการโรงแรมจะเปลี่ยนบนเว็บเมื่อกดบันทึกโปรแกรมเท่านั้น รูปที่เอาออกจะถูกลบหลังบันทึกเมื่อไม่มีวันอื่นใช้ รูปที่อัปแล้วแต่ไม่ได้บันทึกจะค้างในโฟลเดอร์ของโปรแกรม การนำเข้า JSON เติมได้เฉพาะชื่อโรงแรมผ่าน `hotel_options`

## ใบอนุญาตประกอบธุรกิจนำเที่ยว

แก้เลขที่ ชื่อผู้ได้รับใบอนุญาต และรูปได้ที่ `/admin/settings` (ต้องมีสิทธิ์ตั้งค่าเว็บไซต์) เลขและชื่อแสดงใน Footer ทุกหน้าสาธารณะและใต้ปุ่มจองในหน้าโปรแกรม ปุ่ม "ดูใบอนุญาต" ใน Footer เปิดรูปบนหน้าเดิม และไม่แสดงเมื่อไม่มีรูป

ค่าเริ่มต้นคือใบอนุญาต 11/08038 ของบริษัท ทราเวลซี้ด จำกัด รูป `public/images/tour-license.png` ใช้เฉพาะกับเลขนี้เท่านั้น เมื่อเปลี่ยนเลขต้องอัปโหลดรูปใหม่หรือเลือกลบรูปเดิม เพื่อไม่ให้เลขกับเอกสารไม่ตรงกัน รูปที่อัปโหลดเก็บใน `public/uploads` และรูปเก่าจะถูกลบเมื่อบันทึกรูปใหม่สำเร็จ

## จำกัดการเข้าชมระหว่างเตรียมเว็บไซต์

ระบบเปิดการจำกัดหน้าบ้านเป็นค่าเริ่มต้นเมื่อยังไม่มีการตั้งค่า ผู้เข้าชมจะถูกส่งไป `/site-login` รวมถึงการเปิดหน้าย่อยโดยตรง แอดมินที่เข้าสู่ระบบและบัญชียังใช้งานได้สามารถดูหน้าบ้านได้ทันที

เข้า `/admin/site-access` (ต้องมีสิทธิ์ตั้งค่าเว็บไซต์) เพื่อตั้งชื่อผู้ใช้และรหัสผ่านร่วมสำหรับผู้รับเชิญ หรือปิดสวิตช์เพื่อเปิดเว็บไซต์ให้ทุกคนเข้าชม เมื่อยังไม่ตั้งรหัสผ่าน ผู้เข้าชมเข้าไม่ได้ ส่วนแอดมินเข้าได้ทาง `/admin/login` รหัสผ่านผู้เข้าชมต้องมีอย่างน้อย 12 ตัวอักษรและไม่เกิน 72 ไบต์ เก็บเฉพาะ hash บัญชีนี้ไม่มีสิทธิ์เข้าแอดมิน

การบันทึกการตั้งค่าจะยกเลิก session ผู้เข้าชมเดิม และการเข้าชมมีอายุสูงสุด 2 ชั่วโมง หากเว้นช่องรหัสผ่านว่างหลังตั้งไว้แล้ว จะใช้รหัสผ่านเดิม มี CSRF และจำกัดการลองรหัสผิด 8 ครั้งต่อ IP ใน 15 นาที หน้าในโหมดจำกัดการเข้าชมส่ง no-store และ noindex โดยหน้าเข้าสู่ระบบผู้เข้าชมไม่โหลด tracking

ใช้ตาราง `settings` และ `login_attempts` เดิม ขอบเขตการป้องกันคือหน้าเว็บที่ผ่านแอปพลิเคชัน ไฟล์รูปและเอกสารใน `public` ยังเข้าถึงได้ด้วย URL ของไฟล์โดยตรง


## Meta Tag ของหน้าเว็บ

เข้า `/admin/seo` (ต้องมีสิทธิ์ `seo.manage`) เพื่อแก้ชื่อหน้า คำอธิบาย คำค้น และรูปแชร์ของหน้าที่ไม่มีฟอร์มแก้ไขของตัวเอง 10 หน้า ได้แก่ หน้าแรก, `/tours`, `/tours-with-flight`, `/land-tours`, `/packages`, `/gallery`, `/blog`, `/aboutus`, `/contactus` และ `/privacy` รายการนี้กำหนดใน `seo_pages()` ส่วนโปรแกรมทัวร์ โซน/ประเทศ/เส้นทาง และบทความ ตั้งค่า SEO ในฟอร์มของแต่ละรายการตามเดิม

ช่องที่เว้นว่างใช้ค่าเริ่มต้นของหน้านั้น หน้าแรกและหน้ารวมทัวร์ใช้ข้อความและรูปจากแบนเนอร์ ค่าทั้งหมดเก็บในตาราง `settings` ด้วยคีย์ `seo_{หน้า}_title`, `_description`, `_keywords` และ `_image` จึงไม่ต้องมี migration

รูปแชร์ต้องเป็น JPG, PNG หรือ WebP ไม่เกิน 5 MB และมีขนาดอย่างน้อย 1200 × 630 px ระบบ (`App\Support\ShareImage`) ครอปกึ่งกลางแล้วบันทึกเป็น JPEG 1200 × 630 px ไม่ขยายรูปที่เล็กกว่านี้เพราะจะแตกเมื่อแชร์ ส่วนที่โปร่งใสจะเป็นสีขาว และรูปเดิมจะถูกลบเมื่ออัปโหลดรูปใหม่หรือนำรูปออก ฟีเจอร์นี้ต้องใช้ PHP extension `gd` และใช้ `exif` เพื่อหมุนรูปจากมือถือให้ถูกทิศ

Facebook และ LINE เก็บข้อมูลหน้าไว้ชั่วคราว หลังแก้ไขให้กด “Scrape Again” ใน Sharing Debugger และโซเชียลจะอ่าน Meta Tag ไม่ได้ระหว่างที่เปิดจำกัดการเข้าชม
